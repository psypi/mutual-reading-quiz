# 독서 대결장

두 사람이 서로 다른 독서 문제를 내고 상대의 답변을 직접 평가하는 1대1 독서 게임입니다. 크림색 바탕, 짙은 초록색 카드와 금색 강조색을 사용합니다. 외부 이미지·폰트·패키지 없이 Node.js와 HTML/CSS/JavaScript로 동작합니다.

## 실행

Node.js 22 이상에서 실행하세요. 별도 설치나 서비스 계정은 필요 없습니다.

```sh
npm start
```

http://127.0.0.1:3000 에 접속합니다. 서로 다른 브라우저 또는 독립된 브라우저 프로필로 테스트하세요. 참가 세션은 브라우저 저장소에 남으므로 실제로 상대에게 줄 링크를 먼저 열지 마세요.

같은 Wi-Fi의 다른 기기에서 접속할 때는 `HOST=0.0.0.0 npm start`로 실행하고, 두 기기 모두 `http://<Mac의 LAN 주소>:3000`으로 접속하세요. 그 주소에서 P1이 방을 만들어야 P2 초대 링크도 해당 주소를 사용합니다. 기본 `npm start`는 이 Mac 안에서만 접속할 수 있도록 loopback에 바인딩합니다.

## 화면 흐름

상단에 서버가 관리하는 `대기실 → 문제 만들기 → 답변 → 평가 → 결과`의 현재 단계를 표시합니다. 나와 상대의 이름·책·범위·진행 상태를 두 카드에 표시하며, 휴대폰에서는 세로로 배치합니다. 단계마다 필요한 카드만 열고 서버에 저장한 내용으로 이어갑니다.

1. **방 만들기·대기실:** 홈에서 방 이름을 적어 ‘방 만들기’를 누르면 P1으로 바로 입장합니다. 한 브라우저에서 여러 방을 만들 수 있고, P1만 홈의 ‘내가 만든 방’ 목록에서 다시 들어가거나 방을 해체할 수 있습니다. 목록은 해당 브라우저에 저장된 P1 참가 정보로 서버가 검증하며, P2에게는 보이지 않습니다. P1은 새로고침 후에도 P2 초대 링크를 다시 복사할 수 있습니다. P2는 그 링크로 입장하며, 두 사람이 접속해 각각 준비한 뒤 P1이 ‘게임 시작’을 눌러야 문제 만들기가 열립니다.
2. **문제 만들기:** 각자 상대에게 낼 책 제목, 독서 범위, 질문, 핵심 답, 채점 기준을 작성합니다. 가상 예시를 채운 뒤 수정해 볼 수도 있습니다. 제출한 문제는 잠기며, 둘 다 제출하면 P1의 ‘답변하기’ 버튼이 활성화됩니다. 핵심 답과 채점 기준은 출제자에게만 반환합니다.
3. **답변:** P1이 ‘답변하기’를 누르면 양쪽 모두 답변 단계로 이동합니다. P1·P2 답안 창은 나란히 보이고, 휴대폰에서는 세로로 배치됩니다. 각자 자기 답안만 입력하며 상대의 작성 중 초안도 실시간에 가깝게 확인합니다. 입력은 자동 저장되어 재접속·새로고침 후 복구되고, 제출한 답변은 잠깁니다.
4. **평가:** 둘 다 답변을 제출하면 자동으로 채점 단계가 열립니다. 상대가 낸 문제의 제출 답안과 내가 작성한 핵심 답·채점 기준을 보고 0~100 정수 점수와 피드백을 입력합니다. 평가도 한 번만 확정합니다. 양쪽 평가가 끝날 때까지 점수와 피드백은 서버 응답에서 숨깁니다.
5. **결과:** 양쪽 평가가 끝나면 두 사람의 점수와 피드백을 함께 공개합니다. 상대가 준 점수가 자신의 최종 점수이며 높은 점수가 승리합니다. 점수가 같으면 무승부입니다.

제출과 저장이 끝나면 각 카드와 상단 알림에 완료 안내를 보여줍니다. 열린 화면은 약 2초마다 서버 상태를 조회합니다. 이름은 게임 시작 전까지만 바꿀 수 있습니다. 단계 건너뛰기, 남의 답안·평가 변경, 제출 내용 수정 요청은 서버가 거절합니다.

## 대기실 · 준비 · 접속 확인

대기실은 예약된 두 자리와 현재 연결을 구분합니다. 참가자 카드에 이름·접속 여부·준비 상태를 표시하고, 휴대폰에서는 준비·퇴장 버튼을 세로로 크게 배치합니다.

| 상태 | 화면과 서버 동작 |
| --- | --- |
| 상대가 아직 없거나 시작 전에 연결이 만료됨 | ‘상대 초대 대기 중’, 양쪽 준비 해제 |
| 상대가 연결됨 | ‘상대 입장 완료’, 이름 저장 후 ‘준비 완료’ 활성화 |
| 한 명만 준비함 | 시작하지 않고 상대 준비를 기다림. ‘준비 취소’ 가능 |
| 두 명 모두 연결되어 준비함 | P1의 ‘게임 시작’만 활성화. 서버가 시작 시각과 문제 작성 단계를 한 번 저장 |
| 시작 후 상대 퇴장·접속 만료 | ‘상대 재접속 대기 중’, 기존 문제·답변·평가·시작 시각 유지 |
| 시작 후 같은 참가자가 돌아옴 | ‘상대 입장 완료’, 기존 게임을 이어감. 다시 준비하거나 새 게임을 시작하지 않음 |

클라이언트는 2초마다 인증된 상태 요청으로 접속을 갱신합니다. 서버는 마지막 요청으로부터 **6초** 동안만 접속을 유효하게 봅니다. 남아 있는 참가자의 다음 조회에 반영되므로 정상적인 네트워크에서는 연결 끊김이 대략 **6~8초 안에** 표시됩니다. 6초보다 짧은 일시적 끊김은 허용하며, 유효시간을 넘겼다가 돌아오면 시작 전 준비는 다시 해야 합니다. 클라이언트가 보내는 참가자 번호·온라인 여부·상대 준비 상태를 신뢰하지 않습니다. 실제 연결을 완벽히 즉시 판별하는 방식은 아니며 마지막 요청에 유효시간을 두는 방식입니다.

P1과 P2 모두 어느 단계에서나 ‘앱 종료’를 누를 수 있습니다. ‘정말 나가나용?’ 확인을 취소하면 그대로 머물고, 확인하면 서버에 퇴장을 알린 뒤 홈으로 돌아갑니다. 이는 현재 접속을 끝내는 동작입니다. 참가 세션은 같은 브라우저에 남아 P1은 자신의 방 목록에서, P2는 기존 초대 링크로 예약된 자리에 다시 입장할 수 있습니다. 탭 닫기·페이지 이동 때도 가능한 경우 `sendBeacon`으로 퇴장을 알리며, 전달되지 않거나 갑자기 인터넷이 끊겨도 서버의 시간 제한으로 처리됩니다. 같은 자리로 여러 탭을 열면 각 탭의 연결을 구분하므로 한 탭을 닫아도 다른 탭이 살아 있으면 접속 중입니다. 마지막 탭의 연결이 끝나야 퇴장으로 처리합니다. 브라우저가 숨긴 탭의 타이머를 제한하거나 휴대폰이 절전 상태에 들어가면 연결이 만료될 수 있으며, 다시 열면 서버 상태를 확인해 복구합니다.

‘방 해체’는 P1만 할 수 있으며 확인 후 두 사람의 진행을 종료합니다. 해체된 방은 내 방 목록에서 빠지고 기존 초대 링크로는 입장할 수 없습니다. 현재는 실수에 대비해 문제·답안·결과 기록을 저장 파일에 남기는 방식이며, 화면에서 되살리거나 영구 삭제하는 기능은 없습니다.

방 이름·해체 시각, 참가자 이름과 초대 링크의 자리 점유, 서버 단계, 게임 시작 시각, 문제·답안 초안과 제출 답안·평가는 저장하지만 **온라인·준비 상태는 저장하지 않습니다**. 서버 재시작 시 시작 전 대기실은 연결과 준비를 다시 확인합니다. 이미 시작된 게임은 재접속해서 계속 진행하며 시작 요청이 중복되어도 시작 시각을 바꾸지 않습니다. 이전 버전에서 이미 제출한 내용이 있는 대결도 가능한 단계로 복원합니다.

시작 전에는 화면에서 게임 카드를 숨기는 것뿐 아니라 서버도 문제·답변·평가 제출을 거절합니다. 두 사람이 접속 중이고 모두 준비된 상태에서 P1만 서버에 시작을 요청할 수 있습니다. 이후 문제 제출·답변 시작·채점·결과 단계 전환도 제출 상태와 P1 권한을 서버가 확인합니다.

## 문제와 평가의 비공개 범위

핵심 답과 채점 기준은 **그 문제를 낸 참가자의 응답에만** 포함됩니다. 상대에게는 책·범위·질문만 반환합니다. 브라우저에서 내용을 숨기는 방식이 아니며, 결과가 나온 뒤에도 상대의 핵심 답과 채점 기준을 보내지 않습니다. 내 화면의 ‘출제자 전용 메모’와 평가 카드의 ‘내 질문·핵심 답·채점 기준 확인’에서만 볼 수 있습니다.

각 세션의 역할은 서버가 결정합니다. 참가자 번호를 바꿔 보내도 다른 사람의 역할이 되지 않습니다. 답안 초안은 의도적으로 상대에게 보이며, 각자는 자기 자리의 초안만 저장할 수 있습니다. 문제를 낸 참가자는 상대의 답안을 평가하며 자기 답안을 직접 채점할 수 없습니다. 자신이 입력한 평가는 다시 볼 수 있지만, 자신이 받은 점수와 피드백은 양쪽 평가가 끝나야 반환합니다. 최종 결과에는 P1이 받은 점수( P2가 채점 )와 P2가 받은 점수( P1이 채점 )를 따로 표시합니다.

## 두 자리와 초대 링크

대결마다 서로 다른 무작위 초대 토큰을 발급합니다. 링크를 처음 연 브라우저가 해당 자리를 사용하고 별도의 무작위 참가 세션을 localStorage에 보관합니다. 서버는 자리 배정을 순서대로 처리하고 저장 완료 후 확정하므로 같은 자리에 동시에 접속해도 한 세션만 참가합니다. 이미 점유한 링크는 다른 브라우저에서 쓸 수 없습니다. 만석이면 ‘두 참가자 자리가 모두 찼습니다. 이 대결에 참가할 수 없습니다.’라고 안내합니다. 기존 참가자의 재접속은 허용합니다.

링크는 본인 확인 수단이 아닙니다. 먼저 얻어 연 사람이 자리를 차지하고, 생성자는 두 링크를 모두 갖습니다. 두 자리 제한은 실제 사람 수가 아니라 참가 세션 수를 제한합니다. 같은 브라우저 프로필의 탭들은 저장소를 공유하며, 세션을 복사하면 같은 참가자로 접속할 수 있습니다. 링크·세션을 비밀번호처럼 다루세요. 브라우저 기록·복사·스크린샷·확장 프로그램이나 악성 스크립트를 통한 유출은 막지 못합니다.

앱 종료·탭 닫기로 온라인 접속은 종료되지만 초대 링크의 예약된 자리는 해제되지 않습니다. 저장소를 지우거나 다른 브라우저로 바꾸면 원래 자리에 다시 들어갈 수 없습니다. ‘내가 만든 방’ 목록도 같은 브라우저의 P1 정보가 있어야 복원됩니다. 자리 이전·초대 취소·만료·재발급·계정 인증은 아직 없습니다. 공개 운영에는 접근 제한, HTTPS, 인증과 세션 관리가 추가로 필요합니다. 저장 파일에도 참가 권한이 있으므로 다른 사람에게 보내거나 Git에 넣지 마세요.

## 데이터 저장과 원격 공유

기본 저장 위치는 프로젝트의 `data/rooms.json`입니다. 제출마다 임시 파일 기록·flush·파일 교체를 거쳐 저장합니다. 저장 실패 시 이전 파일과 메모리 상태를 유지하므로 실패한 참가가 자리를 소비하지 않습니다. 같은 저장 경로로 서버를 재시작하면 대결·자리·답안·평가를 복원합니다. 손상된 파일을 빈 목록으로 덮어쓰지 않고 시작을 중단합니다. 이전 형식의 파일에서는 참가 권한과 사람의 출제·답변·평가를 유지하고 사용하지 않는 파생 필드를 제거합니다.

두 컴퓨터에서 플레이하려면 **같은 서버의 같은 HTTPS 주소**에 접속해야 합니다. `localhost`나 `127.0.0.1` 링크를 원격 참가자에게 보내면 상대 자신의 컴퓨터를 가리킵니다. 초대 링크는 브라우저의 실제 접속 주소(location.origin)를 기준으로 만들며 localhost나 특정 IP를 고정하지 않습니다. 공유할 주소에서 새 대결을 만들고 링크를 보내세요. 주소가 바뀌면 브라우저 저장소도 달라지므로 기존 자리로 재입장할 수 없을 수 있습니다.

외부 데이터베이스는 필수가 아닙니다. 일시 공유에는 내 컴퓨터와 HTTPS 연결 통로를, 지속적인 운영에는 영구 디스크가 있는 서버 한 대를 선택할 수 있습니다. 임시 파일 시스템을 쓰는 호스팅은 재시작·재배포 시 파일을 잃을 수 있으므로 영구 디스크 또는 별도 저장 서비스가 필요합니다. 여러 서버에서 운영하려면 파일 저장 부분을 트랜잭션을 지원하는 데이터베이스로 바꿔야 합니다. 서비스 가입·결제·외부 연결·실제 인터넷 배포는 이 작업에서 수행하지 않았습니다.

| 설정 | 의미 |
| --- | --- |
| `HOST` | 로컬 기본값 `127.0.0.1`. 원격 서버의 수신 주소는 `0.0.0.0`. 이것만으로 외부 주소나 HTTPS가 생기지는 않습니다. |
| `PORT` | 기본 `3000`. 호스팅이 지정한 값이 있다면 그 값을 사용합니다. |
| `DATA_DIR` | 영구 저장 경로. 기본은 작업 디렉터리와 무관하게 프로젝트의 `data` 폴더입니다. |
| `NODE_ENV=production` | 기본 수신 주소가 `0.0.0.0`이며, 절대 경로 `DATA_DIR`가 없으면 시작을 거절합니다. 실제 영구 디스크인지는 운영자가 확인해야 합니다. |

배포 설정 예시이며, 실행하거나 배포하지 않았습니다.

```sh
NODE_ENV=production HOST=0.0.0.0 PORT=3000 DATA_DIR=/mounted/quiz-data npm start
```

서버 프로세스·복제본은 **하나만** 실행하세요. 같은 저장 경로에 여러 프로세스가 동시에 쓰면 자리 배정과 상태 공유를 보장하지 못합니다. HTTPS는 앞단 프록시·연결 통로에서 처리하고 원래 Host 헤더를 보존하세요. 다른 출처에서 보낸 브라우저 POST 요청은 거절합니다. `/healthz`는 비밀 정보 없이 서버 실행 상태만 알려줍니다.

저장 파일 교체는 백업이 아닙니다. 디스크 삭제·장애·전원 손실까지 보호하지 못합니다. 서버를 멈춘 뒤 `rooms.json`을 별도의 안전한 위치에 복사하고 복원할 때도 서버를 멈추세요. `DATA_DIR`를 `public` 안이나 Git에 두지 마세요.

`Dockerfile`은 실행 코드와 `public`만 이미지에 넣습니다. 기존 `.env`, 대결 데이터, Git 정보는 복사하지 않습니다. 컨테이너를 사용할 때는 `/data`에 영구 볼륨을 연결하고 재생성 후에도 같은 볼륨을 쓰세요. 이미지 빌드·업로드·배포는 하지 않았습니다.
