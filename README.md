# 상호 독서 퀴즈 MVP

Node.js 22 이상에서 `npm start` 실행 후 http://127.0.0.1:3000 에 접속합니다. 외부 패키지 설치는 필요 없습니다. 대결을 만들고 참가자 1·2 초대 링크를 각각 다른 브라우저 또는 독립된 브라우저 프로필에서 엽니다. 각 참가자가 상대의 책·질문·핵심 답안·100점 기준을 직접 출제합니다. 답안을 제출한 뒤 AI 채점 버튼을 누르고, 상대 평가를 확정하면 결과가 공개됩니다. AI 50%, 상대 50%, 동점은 무승부입니다.

## 두 자리와 초대 링크

대결마다 서버가 참가자 1·2에 고정된 서로 다른 무작위 초대 토큰을 발급합니다. 링크를 처음 연 브라우저가 해당 자리를 점유합니다. `/api/join`은 자리 배정을 순서대로 처리하고 저장이 끝난 뒤 확정하므로 같은 자리에 동시 접속해도 한 세션만 허용됩니다. 점유한 브라우저는 별도 무작위 세션을 localStorage에 저장해 새로고침·재접속할 수 있습니다. 서버의 모든 상태 조회·출제·제출·평가는 이 세션에 해당하는 역할로만 처리하며, 요청의 참가자 번호로 역할을 바꿀 수 없습니다. 초대 토큰만으로 점유 후 상태를 읽거나 수정할 수 없습니다.

이미 점유한 링크를 다른 브라우저에서 열면 참가를 거절합니다. 두 자리가 모두 점유됐으면 ‘두 참가자 자리가 모두 찼습니다. 이 대결에 참가할 수 없습니다.’라고 표시합니다. 기존 참가자는 계속 접속할 수 있습니다. 브라우저를 닫아도 자리는 해제되지 않으며, 서버 재시작 후에도 유지됩니다. 브라우저 저장소를 삭제하면 재입장할 수 없고, 현재 자리 이전·초대 취소·재발급 기능은 없습니다. 활성 화면은 2초마다 서버 상태를 조회합니다. 수동 새로고침도 가능합니다.

## 초대 링크 보안의 한계

초대 링크는 계정 인증이나 본인 확인이 아닙니다. 링크를 먼저 얻어 연 사람이 자리를 차지하므로 링크 유출 시 다른 사람이 의도한 참가자보다 먼저 점유할 수 있습니다. 대결 생성자는 두 링크를 모두 가지며 두 역할을 직접 점유할 수도 있습니다. 두 자리 제한은 사람 수가 아니라 서로 다른 참가 세션 수를 제한합니다. 같은 브라우저 프로필의 탭들은 저장소를 공유하며, 세션을 복사하면 다른 브라우저에서도 같은 참가자로 접속할 수 있습니다.

초대 토큰과 세션은 비밀번호처럼 다뤄야 합니다. 링크는 URL 해시로 두어 일반 페이지 요청에 포함되지 않지만, 브라우저 방문 기록·복사·스크린샷·확장 프로그램이나 페이지 내 스크립트를 통한 노출은 막지 못합니다. 세션은 localStorage, 서버 초대 토큰·세션은 `data/rooms.json`에 저장되며, XSS 또는 해당 저장소 접근 권한을 얻은 공격자는 권한을 가져갈 수 있습니다. 만료·회수·로그인·요청 속도 제한은 구현되어 있지 않습니다. 공개 운영에는 HTTPS, 계정 기반 인증과 참가자 연결, 세션 만료·회수, XSS 방어 및 접근 제한이 추가로 필요합니다. 기본 설정은 같은 컴퓨터의 루프백 주소에서만 동작합니다. 원격 공유 설정은 아래를 참고하세요.

## 원격 공유 준비와 저장소 선택

두 사람이 다른 컴퓨터에서 플레이하려면 같은 서버의 **같은 HTTPS 주소**로 접속해야 합니다. 화면과 API는 이 서버가 함께 제공합니다. 정적 페이지 파일만 업로드하면 대결 생성과 상태 공유가 동작하지 않습니다. 로컬에서 만든 `127.0.0.1`/`localhost` 링크를 선배에게 보내면 선배 자신의 컴퓨터를 가리킵니다. 공유할 주소에서 새 대결을 만든 뒤 참가자별 링크를 보내세요. 링크 이동 시 브라우저 저장소의 출처도 달라지므로 테스트용 로컬 대결을 원격 주소로 옮겨 재입장하는 방식은 지원하지 않습니다.

외부 데이터베이스는 현재 구조에 필수가 아닙니다. 두 컴퓨터가 함께 접근할 연결 통로와 계속 켜진 서버는 필요합니다.

| 선택 | 필요한 것 | 데이터 보존과 한계 |
| --- | --- | --- |
| 내 컴퓨터로 일시 공유 | 내 컴퓨터의 앱 서버 + 접근 제한이 있는 HTTPS 터널 또는 사설 네트워크 | 내 디스크에 저장됩니다. 컴퓨터를 켜 두어야 하며, 재접속용 주소가 바뀌지 않아야 합니다. |
| 영구 디스크가 있는 서버 한 대 | Node 서버 + HTTPS 주소 + 재배포에도 남는 저장 공간 | 현재 코드를 그대로 사용할 수 있습니다. 서버 프로세스/복제본은 반드시 하나만 실행합니다. |
| 임시 디스크 호스팅 + 외부 데이터베이스 | 앱 호스팅과 별도 데이터 저장 서비스 | 저장 기능을 데이터베이스의 트랜잭션으로 다시 구현해야 합니다. 여러 서버로 확장하려면 이 방식이 필요합니다. 현재 연결하지 않았습니다. |

호스팅의 임시 파일 시스템은 서버 재시작·재배포 때 내용을 잃을 수 있습니다. 예를 들어 [Render 공식 저장소 설명](https://render.com/docs/disks)과 [무료 서비스 제한](https://render.com/docs/free)은 영구 디스크와 임시 디스크의 차이를 설명합니다. 현재 Render 무료 웹 서비스에는 영구 디스크를 붙일 수 없으므로 이 JSON 저장 방식의 지속적인 운영에 그대로 사용할 수 없습니다. 특정 서비스의 요금제 선택·가입·결제·연결은 수행하지 않았습니다.

### 서버 설정

- `HOST`: 기본 `127.0.0.1`, 원격 서버에서는 `0.0.0.0`. 이것만 바꿔도 인터넷 주소나 HTTPS가 생기지는 않습니다.
- `PORT`: 기본 `3000`, 호스팅이 지정한 값이 있으면 그 값을 사용합니다.
- `DATA_DIR`: 대결 파일을 보관할 경로. 기본은 프로젝트의 `data` 폴더이며 실행한 작업 디렉터리가 달라도 같은 곳을 사용합니다. 배포 시에는 **영구 디스크가 실제로 연결된 절대 경로**를 지정하세요.
- `NODE_ENV=production`: `DATA_DIR`가 없거나 상대 경로이면 서버 시작을 거절합니다. 절대 경로라는 사실만으로 영구 디스크인지는 판별할 수 없으므로 저장소의 보존 정책은 직접 확인해야 합니다.
- `GROQ_API_KEY`: 서버의 비밀 환경변수 전용입니다. 없이도 참가·출제·답안 제출·상대 평가는 가능합니다. AI 채점과 최종 합산 결과는 키와 실제 채점 완료가 필요합니다.

설정 예시(실행·배포한 명령이 아닙니다):

```sh
NODE_ENV=production HOST=0.0.0.0 PORT=3000 DATA_DIR=/mounted/quiz-data npm start
```

HTTPS는 선택한 서버의 앞단 프록시/터널에서 처리하고, 앱과 동일한 주소로 API 요청을 전달하세요. 프록시는 원래 `Host` 헤더를 보존해야 합니다. 서버는 다른 출처의 브라우저 POST 요청을 거절하며, `X-Forwarded-Host` 값을 무조건 신뢰하지 않습니다. 앱 서버 포트를 직접 인터넷에 열기보다 앞단의 접근 제한을 사용하세요. 상태 확인 경로는 `/healthz`이며 키·대결 목록·저장 경로를 반환하지 않습니다.

### 데이터가 보존되는 조건

같은 `DATA_DIR`를 유지하면 자리·출제·답안·평가가 서버 재시작 후 복원됩니다. 저장은 임시 파일 기록과 디스크 flush 후 파일 교체로 수행합니다. 저장 중 오류가 나면 이전 파일과 메모리 상태를 유지하고 실패로 응답하므로 실패한 참가 요청이 자리를 차지하지 않습니다. 손상된 저장 파일은 빈 대결 목록으로 덮어쓰지 않고 서버 시작을 중단합니다. 처리 중 재시작된 AI 채점은 재시도 대기 상태로 복구됩니다.

디스크 자체 삭제·장애, 절전/전원 손실, 파일 경로 변경, 다른 서버로 이동, 영구 디스크 없는 재배포까지 보장하는 백업 기능은 아닙니다. `DATA_DIR`를 `public` 폴더나 Git에 두지 마세요. 서버를 멈춘 뒤 `rooms.json`을 별도 안전한 위치에 복사해 백업하고, 복원할 때도 서버를 멈추고 같은 경로에 배치하세요. 이 파일에는 참가 권한이 들어 있으므로 선배에게 프로젝트 코드와 함께 보내지 마세요.

한 프로세스가 파일과 메모리 상태를 소유합니다. **같은 저장 경로를 쓰는 서버를 두 개 실행하거나 호스팅 복제본을 늘리면 안 됩니다.** 파일 저장은 여러 프로세스 사이의 자리 배정이나 상태 충돌을 해결하지 못합니다. 자동 확장은 끄고 복제본은 1로 지정하세요. 여러 서버가 필요한 경우 외부 데이터베이스와 원자적인 자리 배정이 필요합니다.

### 컨테이너 준비 파일

`Dockerfile`과 `.dockerignore`를 추가했습니다. 이미지에는 실행 파일과 `public`만 복사하며 `.env`, Git 정보, 기존 대결 데이터는 넣지 않습니다. 실제 이미지 빌드·레지스트리 업로드·컨테이너 배포는 하지 않았습니다.

```sh
# 나중에 사용자가 선택한 로컬 환경에서 실행할 예시
# 베이스 이미지 다운로드가 필요할 수 있습니다.
docker build -t mutual-reading-quiz .
docker volume create mutual-reading-quiz-data
docker run --name mutual-reading-quiz --mount source=mutual-reading-quiz-data,target=/data -p 127.0.0.1:3000:3000 mutual-reading-quiz
```

컨테이너를 다시 만들 때도 같은 이름의 볼륨을 연결해야 합니다. 볼륨 자체를 삭제하면 데이터가 사라집니다. 이 명령은 루프백에만 노출하며 외부 주소/HTTPS를 제공하지 않습니다. 실제 키는 이미지에 넣지 말고, 나중에 선택한 실행 환경의 비밀 설정으로 전달하세요.

### 다음에 할 일

1. 아래 검증 결과를 확인하고 코드를 첫 Git 커밋으로 보관하세요. `.env`와 대결 데이터는 제외되어야 합니다. 저장소 공개 여부는 별도로 선택하세요.
2. 잠깐 공유할지, 계속 운영할지 정하고 위 세 가지 방식 중 하나를 고르세요. 가입·결제가 필요한 서비스는 조건을 먼저 확인하세요.
3. 선택한 환경에 Node 22 이상과 서버 하나, 보존되는 저장 경로를 준비하고 `HOST`·`PORT`·`DATA_DIR`를 설정하세요. 재시작·재배포 뒤 테스트 대결이 남는지도 확인하세요.
4. 두 사람이 접속할 동일한 고정 HTTPS 주소와 접근 제한을 마련하세요. 원격 공유에는 별도의 네트워크/배포 검증이 필요합니다.
5. 그 주소에서 새 대결을 만들고 자기 링크를 하나 선택하세요. 선배에게는 다른 참가자의 초대 링크만 비공개로 전달하세요. 링크 전달 전에 선배의 링크를 미리 열면 그 자리를 차지합니다.
6. 두 컴퓨터에서 각각 출제·제출·상태 공유와 세 번째 브라우저의 참가 거절을 확인하세요. 같은 브라우저 프로필과 주소를 유지하세요.
7. AI 채점까지 필요하면 나중에 직접 Groq 계정의 무료 사용 조건을 확인하고 서버 비밀 환경변수에 키를 설정하세요. 이번 준비 작업에서는 실제 키 설정·호출을 하지 않았습니다.

## Groq 연결

계정의 Free 플랜, 모델 권한 및 실제 한도를 확인한 뒤 서버 실행 환경에 `GROQ_API_KEY`를 설정합니다. 키를 소스, 브라우저, 로그, Git에 넣지 마세요. `.env`는 제외되며 `.env.example`에는 빈 값만 있습니다. 키 없이도 출제·제출·상대 평가를 확인할 수 있습니다. 키 발급과 결제 설정은 이 프로젝트가 수행하지 않습니다.

고정 모델은 `openai/gpt-oss-120b`입니다. 무료 여부는 모델 이름이 아니라 계정 플랜에 달려 있습니다. 현재 계정의 무료 접근과 한국어 품질은 아직 검증하지 않았습니다. 유료 플랜으로 연결하지 마세요. 실제 호출 시 반환되는 한도 헤더는 저장되지만 플랜과 모든 한도를 입증하지는 않습니다.

전송 내용은 질문·핵심 답안·채점 기준·응시자 답변뿐입니다. 합계 3,500자 제한은 보수적인 길이 제한이며 토큰 한도 충족을 보장하지 않습니다. 최대 출력 1,800토큰. 전체 답안당 정상 호출 1회, 두 명의 대결은 2회입니다. 서버 전체에서 한 번에 하나만 호출하고 동시 요청은 수동 재시도 안내로 반환합니다. 429에는 대기를 표시하며 자동 예약·재시도·유료/다른 모델 전환은 없습니다.

## 예시 품질 확인

화면의 가상 예시 출제 버튼을 사용하세요. 완전 답안, 같은 뜻의 다른 표현, 핵심 누락, 반대 사실, 빈/무관 답안을 사람이 예상 점수와 함께 준비하고 근거·부분점수·한국어 피드백을 비교합니다. 실제 API 품질 검증은 아직 실행하지 않았습니다. 실제 노트나 개인정보는 사용하지 않습니다.

## 범위와 제한

현재는 서버 한 대에서 실행하는 두 참가자용 MVP입니다. 로컬 기본 설정은 루프백에만 바인딩하며 HOST로 접속 범위를 바꿀 수 있습니다. 참가 링크는 비밀 권한 토큰입니다. 공개 배포 전 HTTPS와 사용자 인증이 필요합니다. 서버 데이터는 Git 제외된 `data/rooms.json`에 저장합니다. 별도 작업 큐는 없습니다. 상대 평가는 총점과 항목별 근거를 수동 입력합니다. AI 응답은 점수 범위와 합계 100점을 검증하지만 출제 기준과 항목 대응의 정확성은 품질 검증에서 확인해야 합니다.

검증: `npm test`. 배포 모드 설정 검사, 저장 실패 시 원상 유지, 손상된 파일 보호, 비밀 파일 접근 거절, 외부 출처 거절, 가짜 키가 포함된 오류의 비노출도 자동 테스트합니다. 채점 테스트는 가짜 HTTP 응답으로 길이 제한, 429, 점수 검증, 전송 필드를 확인하며 실제 Groq API를 호출하지 않습니다. 서버 통합 테스트는 임시 저장소와 실제 로컬 HTTP 서버로 동시 자리 점유, 만석 거절, 역할 검증, 출제·답안·평가 공유, 서버 재시작 후 재접속을 확인합니다.

실제 브라우저 검증: 서로 다른 테스트용 사용자 데이터 디렉터리로 Chrome 두 개를 `--headless --remote-debugging-port=9223` 및 `9224`에서 실행하고, 앱 서버 실행 후 `node scripts/browser-smoke.mjs`를 실행합니다. `QUIZ_BASE_URL`, `CHROME_A_PORT`, `CHROME_B_PORT` 환경변수로 주소·포트를 바꿀 수 있습니다. 이 테스트는 독립된 브라우저에서 대결 생성, 두 참가자의 자동 상태 공유, 만석 안내, 다른 역할 접속 거절과 재접속을 확인하며 테스트 대결 하나를 서버에 남깁니다. 디버깅 포트는 로컬 테스트에만 사용하고 테스트 후 브라우저를 종료하세요.

이번 준비 작업의 검증 결과: 자동 테스트 10개 통과. 로컬 배포 모드 서버에 두 독립된 Chrome을 연결해 자동 상태 공유, 세 번째 브라우저 참가 거절, 링크별 역할과 재접속을 확인했습니다. 네트워크 인터페이스 주소를 통한 같은 상태 조회도 통합 테스트로 확인했습니다. 실제 다른 컴퓨터의 인터넷 접속, 실제 호스팅 재배포, 컨테이너 이미지 빌드, 실제 Groq 호출은 수행하지 않았습니다.
